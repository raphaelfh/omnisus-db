# Entrega v0.1.1 — omnisus-db como ferramenta de montagem e governança de dados abertos

Data: 2026-09-12. Repositório local, sem remote; `main` recebe a tag `v0.1.1`.
Este relatório é o ponto de partida para as duas audiências definidas nesta
sessão: **aplicações** que montam bancos para uso próprio (eficiência,
rapidez, governança) e **pesquisadores** que querem os dados públicos
localmente, em notebook Jupyter ou Marimo. O entregável é a ferramenta que
monta e governa o lake, não um lake pronto.

## 1. O que cada audiência instala

O pacote é puro Python; a roda (`dist/omnisus_db-0.1.1-py3-none-any.whl`) é
gerada com `uv build` a partir da tag. Enquanto não há remote nem PyPI, a
entrega é o arquivo `.whl` (170 KB) ou o sdist (150 KB, só `src`, README,
CHANGELOG e LICENSE).

| Audiência | Instala | Usa |
| --- | --- | --- |
| Aplicação | `pip install omnisus_db-0.1.1-py3-none-any.whl` (Python 3.12) | `import_dataset`, `available`, `policy="skip_same"`, `Lake.publications()`, `LakeReader`; PostgreSQL via extra `postgres` |
| Pesquisador | o mesmo `.whl` mais `marimo` ou `jupyter` | CLI `omnisus-db init/inventory/import/query` e depois `LakeReader(...).connect().sql(...).pl()` |

Documentação: `uv sync --locked --extra docs && uv run mkdocs serve` no
checkout. O site em GitHub Pages passa a existir quando o remote for criado.

## 2. Caminho do primeiro dia, medido

Executado a partir da roda instalada em um virtualenv novo (Python 3.12.13),
em um diretório vazio, fora do checkout, com cache de listagem vazio.

| Passo | Comando | Resultado |
| --- | --- | --- |
| Inicializar | `omnisus-db init` | 3 tabelas auxiliares (`aux_uf`, `aux_municipios`, `aux_cid10`) em 1,7 s |
| Descobrir | `omnisus-db inventory sim_obitos --refresh` | 868 escopos, coluna `Release` (`final`/`prelim`) |
| Importar | `omnisus-db import sim_obitos --plan inventory --year 2023 --ufs RR` | 1 arquivo (289 KB), 3.311 linhas, 3,0 s, exit 0 |
| Consultar | `omnisus-db query "SELECT count(*) FROM lake.sim_obitos WHERE ano=2023 AND uf='RR'"` | 3311, `_source_release = final` |

Em Python, na mesma instalação:

```python
import omnisus_db as odb

scopes = odb.available("sim_obitos", years=[2023], ufs=["RR"])   # [ScopeKey(uf='RR', ano=2023)]
report = odb.import_dataset("sim_obitos", scopes=scopes, policy="skip_same")
# segunda execução: ok 0, skipped 1, failed 0, 0,6 s — nada duplicado

with odb.Lake.local(odb.DEFAULT_TARGET) as lake:
    odb.outdated("sim_obitos", lake=lake)   # [] — nenhum escopo mudou de prelim para final
    lake.publications()                     # [('sim_obitos', ScopeKey(uf='RR', ano=2023), 'final')]

with odb.LakeReader(odb.DEFAULT_TARGET) as reader:
    reader.connect().sql("SELECT ano, uf, _source_release, count(*) FROM lake.sim_obitos GROUP BY ALL").pl()
```

Tamanho no disco depois do import: 248 KB de Parquet e 220 KB de catálogo SQLite.

## 3. Superfície pública congelada

Uma porta genérica para todo dataset do FTP DATASUS e três funções que
carregam comportamento próprio. Não existe alias; o nome do dataset é o nome
da tabela.

| Função | Retorna | Observação |
| --- | --- | --- |
| `import_dataset(nome, scopes=, policy=, ...)` | `ImportReport` | `scopes` vem de `available()` (o que o servidor publica) ou `scopes_for()` (plano cego) |
| `import_cnes_estabelecimentos(...)` | `ImportReport` | CNES-ST mais refresh da view `aux_cnes` |
| `import_cnes_master(...)` | `int` | nomes de estabelecimentos pela API pública; upsert idempotente |
| `import_ibge_populacao(years=, product=)` | `list[ImportResult]` | antes `import_ibge_pop` |

Removidos nesta versão: `import_sim`, `import_sinasc`, `import_sih`. Eram
aliases de uma linha e escondiam `available()` e `policy`, exatamente o que
uma importação repetível precisa. `available()` e `available_releases()`
ganharam `ufs` e `months`, os mesmos seletores de `scopes_for()`; a CLI
`--plan inventory` delega a eles em vez de filtrar depois.

Datasets importáveis: `sim_obitos`, `sinasc_nascidos_vivos`,
`sih_aih_reduzida`, `cnes_estabelecimentos`, a família SIA/APAC
(`sia_bpa_individualizado`, `sia_apac_medicamentos`, `sia_apac_quimioterapia`,
`sia_apac_tratamento_dialitico`, `sia_apac_laudos_diversos`,
`sia_apac_cirurgia_bariatrica`, `sia_psicossocial`), `sinan_chagas`,
`sinan_hanseniase`, `ibge_populacao`. A lista completa e gerada está em
`docs/datasets.md`.

## 4. Governança que a ferramenta entrega

- Proveniência por linha: `_source_ano`, `_source_release` e manifesto de
  publicação por escopo (`Lake.publications()`), com `parser_version` que
  inclui o hash do dicionário.
- Repetibilidade: `policy="skip_same"` ignora um escopo já publicado com a
  mesma fonte e versão; `replace` e `error_if_exists` para os outros casos.
- Final versus preliminar tratado como estrutura, não exceção: uma linha do
  registro com `prelim_dir` é listada nos dois diretórios; `outdated()` diz
  quais escopos migraram e devem ser reimportados.
- Validação de identidade declarada no YAML (`x-identity`): o ano e o código
  do agravo modais do arquivo têm de bater com o escopo pedido.
- Contrato físico: colunas totalmente vazias recebem o tipo do descritor DBF,
  não o do dicionário, para que anos vizinhos convivam na mesma tabela.

## 5. Limites conhecidos

| Limite | Estado | O que fazer |
| --- | --- | --- |
| Python 3.13 sem cargo | `pip install --only-binary=:all:` falha em `datasus-dbc` (sem roda cp313 para macOS/Linux x86_64) | Usar 3.12, ou ter cargo instalado até o upstream publicar rodas |
| Leitor Rust opcional | Não publicado; o Python (`dbfread2`) é o padrão e foi o usado nas medições acima | Sem ação para as duas audiências |
| Site de documentação | Não publicado (sem remote) | `mkdocs serve` local; `docs.yml` publica em Pages quando o remote existir |
| Lakes anteriores a esta versão | Tabelas com nomes antigos (`sim_do`, ...) não são adotadas | Reconstruir em um target novo: "Migrate a legacy lake" em `docs/guides/reprocessing-and-maintenance.md` |
| Medicamentos | Não há fonte pública de eventos de dispensação | `docs/sources/medicamentos.md` e `reports/2026-09-12-sinan-e-dispensacao.md` |
| SINAN além de Chagas e hanseníase | Um agravo é uma linha no registro mais um YAML gerado por `scripts/gen_dicionario.py` | Priorização em `reports/2026-09-12-sinan-e-dispensacao.md` |
